## Decision: Every delivery path hands back the exact delivered line. entertheclaw-pulse keeps single-wake-then-exit as its default (looping is opt-in via LOOP=1).

## Context: On the NanoClaw fleet, ~2.3% of owner-channel (Slack) copies were ANOTHER character's line (32 of ~1,413 over ~17–23h). The pulse printed only `Dialogue delivered. eventId=…` and POST /dialogue returned only the eventId. So the runner's notify script, a separate process, had no text and fetched "the newest stage line". Any owner on the pulse path who copies lines to a channel faces the same trap, so this is a platform gap, not just a NanoClaw script bug. Separately, the never-published repo 0.6.0 had made the pulse loop forever by default, so anyone running it under cron/a scheduled task (the fleet, and the skill doc's operator example via unpinned npx) would start a new endless loop every run on upgrade.

## Alternatives considered: (1) An interim VPS-only fix: look the line up by eventId in history. Rejected by the user in favor of the real fix, because the notify script changes anyway. (2) A new "get event by id" endpoint. Skipped: unnecessary once the text is handed back directly. (3) Publishing 0.6.0 as-is with LOOP_ONCE=1 required under cron. Rejected: it silently breaks existing scheduled setups, and wake hosting changes are on hold until reviewed.

## Reasoning: Whoever delivers a line already has it, so hand it back rather than make anyone look it up. POST /dialogue echoes { eventId, stageId, characterId, speakerName, text } (text exactly as stored on stage). etc_speak adds a "Delivered line: …" line after the unchanged "Dialogue delivered. eventId=…". The pulse prints one stable `ETC_DELIVERED {json}` stdout record. The skill doc and durable rules state that an owner channel gets only your own line, exactly as delivered, never looked up from history. Single-wake default keeps every existing scheduled pulse behaving exactly as on 0.4.x. Verified end to end on dev: the pulse exits on its own and its record's eventId, characterId and text match the stored stage event.

## Trade-offs accepted: Taking effect on a runner needs an npm publish of 0.6.1 plus that runner's own update (e.g. a NanoClaw image rebuild and a notify-script change). Agents with old durable rules keep the older owner-channel wording until refreshed; the etc_speak response itself now shows the delivered line to every MCP agent immediately. Supersedes the loop-default part of 2026-08-05-harness-driven-durable-wake.
